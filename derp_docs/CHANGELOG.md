# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]
### <span style="color: #80ffc0">Added</span>
- <span style="color:#80ffc0"><strong>derpTutorial node</strong></span>: New ControlDeck node (`derpTutorial`) that acts as the first-run welcome mat for derp-UI. Auto-spawns in the graph on fresh installs and on major tutorial version bumps, lists bundled tutorial workflows under `user/derpNodes/workflows/tutorials/` as launch buttons (each opening in a new browser tab via user-gesture click), and provides a "Do not auto show this tutorial again" toggle persisted through `Derp.Tutorial.SuppressMajorVersion`. Supports deep-linking via the `xcpDerpTutorialWorkflow` URL query param and version-stamped sizing migration so saved oversized manual heights compact back to Auto.
- <span style="color:#80ffc0"><strong>derpConcatenate scrollViewport clipping</strong></span>: Signal-entry previews and the concatenated-output preview now clip with a scrollbar in Manual height mode when their text wraps to multiple lines and the node face cannot fit them. Auto height mode still grows the node to fit all content. Two independent viewports (`regionSignalsViewport`, `regionConcatContent`) coordinate available space so the output viewport accounts for the signals viewport's clip delta through a cross-resolver handoff (`node._concatSignalsClipDelta`).
- <span style="color:#80ffc0"><strong>Slider V2 foundation and editor</strong></span>: Added the first `UI_TYPES.SLIDER_V2` widget path with shared INT/FLOAT value helpers, horizontal interaction metrics, Canvas/HTML render-path switching through `Derp.SliderV2RenderPath`, preset style normalization, focused tests, and `derpSkunk` lab wiring. Added the pure virtual `derpSliderV2Editor` utility for previewing Slider V2 styles and saving/loading reusable style JSON through the new `sliderV2Styles` backend category.
- <span style="color:#80ffc0"><strong>"Selected nodes pulse animation" setting</strong></span>: New global toggle under 🔞 Derp Nodes → Optimization → Selection Pulse Animation (`Derp.SelectionPulseAnimation`, default ON). When enabled, selected nodes pulse using the existing 50ms-bucket alpha animation. When disabled, selected nodes render a static `_ON` frame (`paintON` + `_ON` header state) so they remain clearly distinguishable from unselected nodes without any per-frame animation cost.
- <span style="color:#80ffc0"><strong>Deck Pressure top/bottom hub-seam resize</strong></span>: The shared horizontal seam between a top/bottom horizontal branch row and the ImageDeck hub is now height-resizable, mirroring the existing left/right side-width seams. Dragging the seam changes the branch row's height and compensates the hub height inside the preserved Deck frame (side branches refit to the new band), and a 1px seam ghost is drawn across the branch band during both hover and drag. Eligibility is gated at the seam resolver — a row whose members are all preferred-auto-height cannot absorb the delta, so it shows no hitbox, cursor, ghost, or drag affordance at all. Row member widths are frozen for the whole drag via a `_deckPressureTopBottomWidthOverrides` snapshot (same feedback-loop guard as frame edge drags), and the session reuses the `_deckPressureFrameHeightResizeActive` stand-down so Fatha/Uncle draw loops pin member geometry to the plan on both axes until pointer-up.
- <span style="color:#80ffc0"><strong>Deck Pressure outer-frame edge resize</strong></span>: The four outer edges of a Deck Pressure frame (left/right/top/bottom) now expose single-axis resize handles, separate from corner resize. Edge resize operates on the decked stacks attached to that edge, never on the ImageDeck hub itself: left/right edges resize the side vertical stack's width, and top/bottom edges resize the top/bottom horizontal stack's height, while the hub keeps its size and the deck frame expands or shrinks around it (side stacks refit to the new band). This is the key behavioral difference from corner resize — corners resize the hub on both axes while stack sizes stay fixed, while edges resize the stacks on a single axis while the hub stays fixed. If no stack covers the dragged edge, the edge behaves like the hub's own edge (legacy single-node resize).

### <span style="color: #80aaff">Changed</span>
- <span style="color:#80aaff"><strong>Cross-frame text measurement cache</strong></span>: `measureTextWidth()` and `measureTextHeight()` in `widgetsUtils.js` now cache results in a 1000-entry LRU keyed on full font state + visible text, eliminating per-frame `ctx.measureText` calls for widgets that render the same text every draw. Color-key tags are stripped before keying, and the cache auto-clears on webfont `loadingdone` events.
- <span style="color:#80aaff"><strong>Cross-frame color-key parse cache</strong></span>: `parseColorKeyText()` now caches parsed segment results in a 2000-entry LRU keyed on text + state suffix + palette signature (theme cache key, header palette, string-palette path, active palette name). Cache hits skip regex scanning, palette resolution, and segment allocation. Async palette fetches and live palette edits explicitly clear the cache to prevent stale null-color results.
- <span style="color:#80aaff"><strong>Dock seam resize hitbox thickness</strong></span>: Shared-edge resize detection zones for both horizontal and vertical dock seams (including Deck Pressure side seams) are now 4px total — 2px per adjacent node — down from the previous ~10–20px. This prevents seam hitboxes from bleeding into neighboring button detection zones.
- <span style="color:#80aaff"><strong>Selection pulse dirty-rate optimization</strong></span>: The selection pulse animation in `fathaHandler.js` no longer calls `setDirtyCanvas(true, false)` every frame while a node is selected. Because `getPulseAlpha` is quantized to 50ms buckets (`PULSE_FRAME_BUCKET_MS`), the pulse visual only changes ~20 times/sec — but the previous per-frame dirty forced ALL nodes on the canvas to redraw at 60fps, making non-selected nodes go red in the performance tracker and cutting frame rate by ~50% when a derp node was selected. A module-level `requestAnimationFrame` waker now registers selected nodes and only dirties the canvas when the 50ms pulse bucket actually changes, cutting the canvas-wide dirty rate from 60fps to 20fps while keeping the pulse visually identical.
- <span style="color:#80aaff"><strong>Shared canvas rect cache</strong></span>: `getBoundingClientRect()` reads on the canvas element are now served through `getDerpCanvasRect()` in `widgetsUtils.js`, a 32ms TTL cache shared by `calculateScreenCoords()`, the Fatha DOM shield sync (`fathaDOMshield.js`), and the Fatha screen/visible-rect helpers (`fatha.js`). Previously every decked node read the canvas rect independently each frame during pan/zoom, and because `getBoundingClientRect()` forces a synchronous layout flush whenever earlier style writes in the same frame dirtied layout, N decked nodes could cost N layout flushes per frame. The canvas screen rect cannot change mid-frame (pan/zoom only mutates `ds.offset`/`ds.scale`), so one read per TTL window is exact for frame-coherent consumers and self-corrects on window resize/scroll.
- <span style="color:#80aaff"><strong>Paint-data property-name memo</strong></span>: The case-insensitive paint property lookup behind `resolvePaintData()` and Slider V2's exact-paint check is now memoized through a WeakMap-backed `findPaintPropName()` helper in `widgetsUtils.js`. Previously each call scanned `Object.keys(owner)` twice per lookup — per widget, per frame — which scaled with the number of hydrated theme keys on the node. Positive resolutions are memoized per owner and re-validated with a single property read; misses fall through to the live scan, so theme hydration can add or delete paint props without any cross-module cache invalidation.
- <span style="color:#80aaff"><strong>Background parallax no-op guard</strong></span>: The parallax background RAF loop in `derpBackgroundParallax.js` now compares the computed render geometry against the last applied values (`state.lastApplied`) before touching the DOM, skipping CSSOM writes on frames where pan/zoom/resize produced no change. Previously the loop rewrote `width`/`height`/`left`/`top` styles every animation frame even when the canvas was completely idle, keeping the compositor busy for zero visual change.
- <span style="color:#80aaff"><strong>Deck Pressure geometry plan memo</strong></span>: `computeDeckPressureGeometryPlan` in `masterDockEngine.js` now memoizes its read-only plan per hub behind a signature of member topology, geometry, layout hashes, and viewport clip measurements. During pan/zoom every deck member's shield sync and dock maintenance pass used to recompute the full geometry plan per node per frame; now one computed plan is shared by all callers until the signature changes. Resize paths pass explicit options or set transient hub state (`_deckPressureSideWidthOverrides`, `_deckPressureTopBottom*Overrides`, frame-height resize flags) and always bypass the memo, so live drags still plan against fresh geometry. Scroll positions are deliberately excluded from the signature (the plan never reads `scrollTop`), so ordinary viewport scrolling never invalidates it.
- <span style="color:#80aaff"><strong>DOM shield structure/transform hash split</strong></span>: `syncDerpShield` in `fathaDOMshield.js` now splits its state hash into a graph-space structure hash (node pos/size, deck edges, neighbors, pressure topology, auto prefs, plus a full dock-group signature covering sibling collapse/height-mode/geometry/edge state) and a screen-space transform hash (scale, offset, canvas rect, link pads). During pan/zoom only the transform hash changes, so the resize-eligibility predicate battery — linear-stack walks, pressure seam resolvers, frame corner/edge checks — is reused from a per-shield cache and only the cheap pixel styles re-apply. The group signature keeps the cache honest: a sibling toggling height mode or collapsing invalidates eligibility immediately, rather than relying on the incidental pan/zoom invalidation the old single hash provided.

### <span style="color: #ffc680">Fixed</span>
- <span style="color:#ffc680"><strong>Deck frame bottom edge resize hitbox</strong></span>: The shared top/bottom edge handles for Deck Pressure frame outer edges and hub seams now extend outward by the same 5px pad the corner handles use (`SHIELD_CORNER_RESIZE_OUTWARD_PAD`), so the grab zone straddles the visual frame edge instead of stopping at the node's logical bounds. The body drop shadow is offset downward (`shadowOffsetY`), which pushes the perceived bottom edge a few pixels below `node.size` — with the old inward-only 2px strip, hovering the visual bottom edge of a deck produced no resize cursor until the pointer moved a few pixels above the edge.
- <span style="color:#ffc680"><strong>Deck Pressure top/bottom branch outer side-edge resize</strong></span>: Dragging the outer left edge of the leftmost member (or outer right edge of the rightmost member) of a horizontal branch row decked above/below the ImageDeck hub now resizes the whole Deck frame width on that side, instead of merely rebalancing the row's internal member widths while the frame width stayed put. The outer edge of a top/bottom branch row lies exactly on the Deck frame boundary, but `applyDeckPressureSideWidthResize` rejected these drags because the member's branch side is `top`/`bottom`, so the gesture fell through to ordinary horizontal-stack width resize. The fix mirrors the established frame-edge contract for both deck shapes: when a left/right vertical branch covers that side, `syncDockResizePair` detects the frame-aligned outer row edge (`getDeckPressureRowSideRedirect`) and reruns the drag through the adjacent side branch's outer-frame side-width resize (forwarding the snapped pointer delta), expanding the frame while the hub stays fixed; when NO side branch exists (hub + bottom/top row only), the row's outer edge coincides with the hub's own outer edge, so `startResize` routes the drag to the hub itself — `handleNodeResize`'s hub path resizes the hub width and refits the row via `applyDeckPressureLayout`, behaving exactly like dragging the ImageDeck's own left/right edge. Once a session starts it stays authoritative for the whole drag, so the row's mid-drag refit cannot reclassify the gesture back to a row rebalance.
- <span style="color:#ffc680"><strong>Deck Pressure frame-height edge drag flicker</strong></span>: Dragging a deck frame's top/bottom outer edge no longer makes branch members flicker, disappear, open gaps, or constantly change width mid-drag (previously corrected only on mouse release). While `hub._deckPressureFrameHeightResizeActive` is set, the Fatha and Uncle draw loops pin every deck member's width AND height targets to the plan-assigned physical size and stand down the per-draw horizontal shared-height sync, `balanceHorizontalDeckWidthChange`, and the auto-axis `properties.nodeSize` writes — the Deck Pressure plan owns member geometry on both axes for the whole drag via `_deckPressureTopBottomHeightOverrides`. Previously each member's per-frame auto width/height targets and the max-member shared-height sync overwrote the plan's band rects every frame, fighting the live resize. Row member widths are additionally frozen for the whole drag via a drag-start `_deckPressureTopBottomWidthOverrides` snapshot consumed by the plan, so a height-only edge drag can no longer re-fit row widths from live measurements — previously a transiently self-inflating member (e.g. fixed-width `derpSeedV3`) fed its own inflated width back into the row fit and kept growing wider until mouse release.
- <span style="color:#ffc680"><strong>Deck Pressure min-span measurement layout corruption</strong></span>: `getDeckPressureMinSpanForState` now restores the measured node's live layout to its real collapse state at its real height after simulating collapsed/expanded spans, and snapshots content viewport scroll positions before measuring. Previously the restore pass recomputed the expanded layout map at the collapsed probe height (`snap*2`), collapsing anchored fill regions and pinning loader bottom rows to the node top. Because branch members can reach Deck Pressure layout re-entrantly from their own draw cycle, the corrupted regions were painted the same frame — causing the loader row flicker during left side-branch seam resizes — and stale measured minima could push a right side stack taller than the deck band until the bottom node lost its resize handles.
- <span style="color:#ffc680"><strong>ImageDeck auto-fit Deck Pressure resizing</strong></span>: ImageDeck auto-adjusted height changes from portrait/landscape image aspect switches now resize attached Deck Pressure branches as a programmatic frame-height change, keeping side stacks expanded and aligned instead of pressure-collapsing branch members or leaving stale branch geometry.
- <span style="color:#ffc680"><strong>Deck Pressure frame-height corner resize</strong></span>: ImageDeck corner height resizing now clamps to the active side-vertical branch floor and keeps expanded side-stack members expanded during the live drag, preventing accidental collapses, disappearing collapsed headers, and stale hitboxes after release.
- <span style="color:#ffc680"><strong>Deck Pressure side-vertical live resize</strong></span>: Left/right vertical Deck Pressure branches now preserve active branch member heights during internal seam resizing while the branch still fits the side band, and lower internal seams prime the full branch before the first pointer move. This prevents flicker and unrelated sibling height changes during the drag.
- <span style="color:#ffc680"><strong>Deck Pressure side-vertical auto-height seams</strong></span>: Internal seams in left/right vertical ImageDeck branches now remain draggable even when branch members preserve preferred Auto Height mode, because Deck Pressure owns their live fitted heights while docked. Ordinary auto-height vertical stacks still keep their seams blocked.
- <span style="color:#ffc680"><strong>Deck Pressure horizontal seam regression</strong></span>: The branch-member pass-through added for outer-frame edge resize was swallowing `left`/`right` pointerdowns on Deck Pressure branch members that sat on real internal sibling seams (top/bottom horizontal branches, side-horizontal branches). The pass-through re-invoked `shield.onpointerdown`, which re-detected the same seam and recursed, so the drag never started even though the ghost edge and cursor still appeared. `startResize` now lets the drag proceed when `canResizeHorizontalSharedEdge` is true — the same predicate the ghost, cursor, and hit-test paths use — so affordance and execution stay in sync.
- <span style="color:#ffc680"><strong>Deck Pressure side-seam resolver ignoring branch-side guard</strong></span>: `resolveDeckPressureSideSeam` in `fathaDOMshield.js` was incorrectly classifying a top/bottom horizontal branch member's outer left/right edge as a side seam when the row spanned the full Deck frame width, because its coordinate-based fallback matched the member's edge X against the hub's left/right X without checking which branch the member belonged to. This caused `hubSeamResizeEarly` to pre-empt the internal-seam and frame-edge disambiguation paths, routing the gesture to the wrong resize target. Added the same branch-side guard that `resolveDeckPressureTopBottomSeam` already has — a member whose `directBranchSide` is `top`/`bottom` cannot be a side seam — so top/bottom members correctly fall through to frame-edge detection, internal seam detection, or pass-through.
- <span style="color:#ffc680"><strong>Fatha live resize height pinning</strong></span>
- <span style="color:#ffc680"><strong>derpTriggerWall bottom selector spacing</strong></span>: TriggerWall now keeps trigger groups packed at `sH`, lets the bottom trigger group-to-LINEBREAK gap shrink to `mH`, prevents viewport-backed manual resize floors from preserving expanded vertical spring space, avoids margin-only scrollbars, and clips trigger groups before they can draw over the bottom selector.
- <span style="color:#ffc680"><strong>derpConcatenate Auto/Manual height layout</strong></span>: Concatenate now keeps Auto height mode tightly packed with no wasted spring space, while Manual height mode bottom-aligns the add-signal LINEBREAK/dropdown group and places surplus height only above that group. The layout hash now includes runtime height mode so switching Auto/Manual rebuilds the correct layout structure.
- <span style="color:#ffc680"><strong>derpConcatenate docked Auto-height shrink</strong></span>: Concatenate now settles content-height changes against the user's preferred Auto Height Mode even when a vertical stack temporarily owns runtime height, so collapsing signal previews or the concatenated text display can shrink the docked node instead of only allowing expansion.
- <span style="color:#ffc680"><strong>derpTriggerWall trigger drag-and-drop</strong></span>: Trigger items now keep their drag state separate from trigger-group reordering, can move across visible trigger groups, and show destination placement as an empty measured slot instead of drawing a duplicate trigger. Pointer-up is the only commit point, preventing accidental drops or frozen group regions while dragging.
- <span style="color:#ffc680"><strong>Slider V2 Canvas/HTML effect parity</strong></span>: Slider V2 now uses V2-owned Canvas and HTML visual parts for background, fillbar, knob, btnLR, and label rendering. Canvas and HTML shadow/glow handling now share the same alpha, offset, clipping, fallback, and negative-chamfer glow behavior, including visible HTML glow layers through `masterPainterHTML` for DK_Galactica-style `button._ON` fallback paints.
- <span style="color: #ffc680"><strong>Stack/deck docking audit pass</strong></span>: Comprehensive audit of the docking system addressing seam resize inconsistencies, autoHeight content overflow during resize, and Deck Pressure branch lifecycle issues. Changes span six framework files and resolve the recurring glitches reported when mixed node types (fixed-width nodes like `derpSeedV3`, autoHeight nodes, and clipped viewport nodes) are docked together.
  - <span style="color:#ffc680"><strong>Seam resize minWidth clamping</strong></span>: `getDockNodeMinWidth` counterpart calls in `dockResize.js` no longer pass the entity's own minWidth as the fallback, preventing one node's minWidth from inflating the neighbor's resize floor and stalling the seam short of its intended position.
  - <span style="color:#ffc680"><strong>Collapsed-boundary height pinning</strong></span>: The collapsed-boundary growth path now sets `_dockResizePreserveHeight` on the target member so the draw cycle cannot override the manually dragged height with content-measured height mid-gesture.
  - <span style="color:#ffc680"><strong>Uncle node seam dead zones</strong></span>: `getSharedResizeAnchorAtPointer` in `fathaDOMshield.js` now accounts for Uncle `padL`/`padR` link-dot padding when computing the horizontal seam hit-test threshold, eliminating dead zones where left/right seams on docked loader nodes refused to drag.
  - <span style="color:#ffc680"><strong>Vertical seam JS fallback</strong></span>: Added top/bottom vertical seam detection to the JS hit-test fallback so vertical shared edges remain draggable even when DOM strips are obscured.
  - <span style="color:#ffc680"><strong>autoHeight content overflow</strong></span>: Both `dockDimensions.js` and `settleDerpSizeBeforeDrawImpl` in `dockResize.js` now prefer `contentMinHeight` over `totalHeight` for autoHeight nodes, preventing `footerRegion` with `height: "fill"` from inflating node height and pushing content outside boundaries during seam resize.
  - <span style="color:#ffc680"><strong>Viewport clip height floor</strong></span>: `getVisibleRegionLayoutFloor` prefers `minClipHeight` over the live `clipHeight` so Fit Node clipped regions can shrink to one visible entry/group during seam resizing instead of locking to the current visible height.
  - <span style="color:#ffc680"><strong>Deck Pressure side-seam geometry check</strong></span>: `isDeckPressureHubSeamSideEdge` now verifies the hub geometry aligns with a side-width resize edge via `isDeckPressureSideWidthResizeEdge`, and `canResizePressureSideHorizontalLeftW/RightW` are gated on the same check, preventing phantom resize handles on misaligned hub seams.
  - <span style="color:#ffc680"><strong>Deck Pressure vertical seam strip inset</strong></span>: Vertical seam DOM strips now always use the corner inset regardless of pressure membership, keeping shared-edge strips consistent across Deck Pressure and ordinary vertical stacks.
  - <span style="color:#ffc680"><strong>Deck Pressure branch undeck ordering</strong></span>: `undeckDeckPressureBranches` in `masterDockEngine.js` now captures all branch members before `disconnectPeerDeckEdge` clears the edge metadata, so `clearDeckPressureSideHorizontalWidthLock` runs against the full member list instead of an empty one.
  - <span style="color:#ffc680"><strong>Node removal dock cleanup</strong></span>: `fatha.js` and `uncle.js` `onRemoved` hooks now undeck Deck Pressure branches (when the removed node is a hub) and then undeck the node itself, preventing stale `deckParentId`/`deckEdges` references from corrupting the dock graph when nodes are deleted while docked.
  - <span style="color:#ffc680"><strong>Dead import removal</strong></span>: Removed the unused `canResizeHorizontalStackWidth` import from `dockResize.js`.
- <span style="color: #ffc680"><strong>Stack/deck engine audit hardening pass</strong></span>: Second full audit of the stack/deck system covering engine cache-key contracts, Deck Pressure caches, and clipped-viewport resize floors.
  - <span style="color:#ffc680"><strong>Layout cache hash contract</strong></span>: Engine cache keys (layout engine, Deck Pressure min-span, resize sessions, Basta, whole-wall caches) now combine the node structure hash with the shared header inset hash (theme, collapse, `drawHeader`, selection, corners) through `getDerpLayoutCacheHash`. Header toggles and theme switches on decked nodes no longer serve stale layouts or stale cached panels.
  - <span style="color:#ffc680"><strong>Deck Pressure side-height invalidation</strong></span>: Preserved side-branch heights now carry a per-member signature (collapse state + viewport clip measurements), so collapse toggles from any path and loader content edits refit the branch instead of restoring stale heights; ordinary scrolling never invalidates.
  - <span style="color:#ffc680"><strong>Vertical seam min-height freeze</strong></span>: `syncDockResizePair` now freezes `topMinH`/`bottomMinH` into the seam session, fixing oscillation/flicker when dragging seams next to viewport-clipped loader nodes whose content minimum changes with height.
  - <span style="color:#ffc680"><strong>Width-lock release guard</strong></span>: Deck Pressure side-horizontal restore paths now release `_horizontalDeckWidthResizeLock` through a session-stamped helper, so a stale 250ms timer can no longer clear a lock owned by a newer dock/undock session.
  - <span style="color:#ffc680"><strong>Dock floor accuracy</strong></span>: `getDockNodeMinHeight` now deep-walks nested layout regions for explicit `minHeight` values, and collapsed Deck Pressure floors use the same `Math.max(contentMinHeight, totalHeight)` contract as the dock-resize floor, keeping resize floors consistent across paths.
- <span style="color: #ffc680"><strong>Horizontal stack outer-edge width resize distribution</strong></span>: Dragging the left or right outer resize handle of a horizontal stack now distributes the width delta across all resizable (manual-width) members, stopping only when every resizable member reaches its own min-width. Previously, when the corner node was a manual-width node (`autoWidth = false`), the stack distribution path was skipped because it was gated on `!resizeAxes.allowWidth`, and the resize fell through to the single-node clamp path — stopping as soon as the corner node itself hit its min-width instead of shrinking the other members. autoWidth/fixed members keep their original width during the distribution.
- <span style="color: #ffc680"><strong>Vertical stack Manual-mode height preservation</strong></span>: `normalizeSharedEdgePair` for left/right edges (a vertical stack docked beside an ImageDeck) no longer calls `fitSizesToTotal` on columns containing any manual-height member. Previously, choosing a dropdown item on one node that didn't change its height could still trigger proportional redistribution of all stack members' heights. Manual members now keep their current height; only all-auto (Scale mode) columns scale to match the shared deck height.
- <span style="color: #ffc680"><strong>Standalone node autoWidth/autoHeight restoration after undock</strong></span>: `restoreDeckNodeAxes` now unconditionally deletes both `_derpPreferredAutoWidth` and `_derpPreferredAutoHeight` on undock, and `resolveDerpPreferredAutoHeight`/`resolveDerpPreferredAutoWidth` only honor those overrides when the node is actively docked (has the corresponding `deckSaved*` property). This fixes standalone nodes being stuck in Manual mode (seam resize blocked, width/height not auto) after removal from a stack that was attached in Manual deck-fit mode.
- <span style="color: #ffc680"><strong>Seam ghost visibility on autoWidth/autoHeight edges</strong></span>: `updateSharedResizeHoverSession` in `fathaDOMshield.js` now re-checks pair eligibility via `canResizeVerticalSharedEdge` before using a stale `_resizeAnchorOverride` fallback for repurposed corner handles. Previously, if a neighbor's autoHeight state changed after the last shield sync, the green seam ghost could still appear on edges where one neighbor was auto — even though the drag itself was correctly blocked at `pointerdown`. Horizontal stacks were already protected by `getSharedResizeAnchorAtPointer`; the fix makes vertical stacks symmetric.
- <span style="color: #ffc680"><strong>Layout engine fill-height rebalance</strong></span>: `masterLayoutEngine.js` now runs a final top-level fill-rebalance pass after all root siblings are fully measured, recalculating `height: "fill"` regions (including anchored fills) from actual sibling dimensions instead of the previous 12px fallback estimate. This fixes overflow where auto-height siblings appearing after a fill region (e.g., a bottom-pinned loader row after a model list spring) were pushed outside the node boundary because the fill region incorrectly absorbed their space. Fill-height column regions (non-`scrollViewport`) expand to contain their children during measurement (CSS `min-content` behavior), so auto-height mode correctly measures content without child overflow. `totalHeight` uses `contentMinHeight` (computed at zero-height in PASS 1) to prevent deck-pressure sizing from seeing inflated fill heights. `minHeight: 0` is now correctly treated as zero instead of being falsy-falling back to 12px. `_childConfigs` is stored on every region during processing for safe child iteration without iterating computed layout props.
- <span style="color: #ffc680"><strong>derpModelLoader vertical spring</strong></span>: The model loader node now uses a proper `height: "fill", minHeight: 0` spring between the loaded models deck and the bottom LINEBREAK + FILEBROWSER row, pushing loader controls to the node bottom in Manual height mode while collapsing the spring in Auto height mode. Uses the two-sibling `derpNotes` pattern (anchored fill container + flow auto loader region) with `footerHeight = 6 + mH` to reserve theme-accurate spacing above the system panel button. Minimum node height correctly prevents shrinking past the actual content (deck + LINEBREAK + loader + footer) via `contentMinHeight` recursion and `compactFloor` including header and `footerHeight`.
- <span style="color: #ffc680"><strong>derpTutorial excessive empty space (PASS 1 wrap text inflation)</strong></span>: `derpTutorial`'s `introText` widget with `wrap: true, width: "full"` was inflating `contentMinHeight` from ~118 to ~922 during PASS 1 of the layout engine, because `interpretLayoutProps` in `widgetsUtils.js` used the squished `context.geometry.w` (`SQUISH_WIDTH = 10`) as the wrap boundary — wrapping a ~90-char string into ~75 lines. `settleDerpSizeBeforeDrawImpl` then consumed the inflated `contentMinHeight` as the auto-height, leaving the node with excessive empty space at the bottom. `masterLayoutEngine.runLayoutPass` now propagates an `isMeasurePass` flag through the layout context, and `interpretLayoutProps` uses the host node's physical width (`context.owner.size[0] - padW - 20`) as the wrap boundary whenever `isMeasurePass === true`, so PASS 1 wrap measurement matches the PASS 2 display layout instead of the rigid floor probe.

## [0.7.10] - 2026-06-24
### <span style="color: #80ffc0">Added</span>
- <span style="color: #80ffc0"><strong>ICONBUTTON corner guard</strong></span>: `btnIcon.js` now guards background corners against undersized buttons before both HTML and Canvas rendering. The default guard ratio is 4.0`, using the larger absolute value of top-left/top-right for width checks and top-left/bottom-left for height checks. If the button is too small, each corner magnitude steps toward `0` by `1`, preserving negative chamfer signs while preventing oversize corners from drawing.
- <span style="color: #80ffc0"><strong>ICONBUTTON palette background entries</strong></span>: Theme-attached palette files can now define `_ICONBTN_<icon>` entries, where `<icon>` matches a `btnIcon.js` `ICON_MAP` key such as `_ICONBTN_add`. Matching ICONBUTTON widgets replace only their background rect paint from the palette entry, including hover/press/pulse animation colors, while keeping glyph color, geometry, and normal icon text styling unchanged.
- <span style="color: #80ffc0"><strong>Deck Pressure side-seam width resizing</strong></span>: Deck Pressure side branches can now be resized from the shared vertical seam on the `derpImageDeck` hub. Dragging the hub-facing left/right seam changes the side stack width while the overall Deck frame stays anchored, including decks with top or bottom branches.
- <span style="color: #80ffc0"><strong>Deck arrangement modes</strong></span>: Added `Derp.DeckArrangement` under Docking and Decking with `Automatic`, `Vertical Sandwich`, and `Horizontal Sandwich` modes for new Deck Pressure layouts. Empty `derpImageDeck` hubs persist their resolved `properties.deckArrangement` on first branch attach, existing decks default to vertical sandwich, and later global setting changes do not rearrange decks that already have members.

New `richImageContent` config flag switches the editor to `innerText`-based DOM sync via `getDerpEditorDomValue`/`setDerpEditorDomValue` helpers, preserving image embeds through focus/blur/escape transitions.
- <span style="color: #ffc680"><strong>Panel layout margins</strong></span>: `fathaLayoutMaps` panel base map left margins zeroed (`mW` → `0`) to remove unnecessary left gutter. `mouseOver: false` added to `lblTheme`.
- <span style="color: #ffc680"><strong>derpSeedV2 system panel</strong></span>: History/log editors switched from `EDITOR_HTML` to `EDITOR` with `canvasShield`. Margins tightened. "Lucky Num" row removed.
- <span style="color: #ffc680"><strong>derpSchedulerLoader / derpLoraStack</strong></span>: Browser theming fixed (`dialog, t_textNormal` + `fontSize`), root name localized. `mouseOver: false` on dropdowns.
- <span style="color: #ffc680"><strong>Node titles stuck in previous locale after switching languages</strong></span>: Title localization now uses a default-title registry built from all available locale files. `syncDerpLocalizedDefaultTitle()` auto-replaces known default titles with the active locale's version on locale load, theme update, and node configure. Custom user-renamed titles (via double-click or settings text field) are flagged with `_derpCustomTitle = true` and excluded from auto-localization, so user edits survive locale switches.
- <span style="color: #ffc680"><strong>Stack drag-and-drop click-vs-hold</strong></span>: Every `onPress` handler in derpConcatenate now cancels any pending drag state via `cancelConcatStackDrag()` before executing its action, preventing stale drag timers from activating on subsequent clicks. Layout hash and `refreshNodeLayoutMap` calls are gated behind `_dragThresholdMet` so the hold period doesn't thrash the layout.
- <span style="color: #ffc680"><strong>Regional `onDragEnd` dispatch</strong></span>: `handleShieldDragStart` now saves the hit region key as `_dragEndRegionKey` when the region has drag handlers. `endDockDrag` dispatches `onDragEnd` to the correct region instead of relying solely on `_pressedRegionKey`, which could be stale when multiple regions were involved.
- <span style="color: #ffc680"><strong>Wrapped text color-key rendering</strong></span>: `textLabel` now slices color segments per-line via `getLineColorSegments()` / `sliceColorSegmentsByVisibleRange()`, so wrapped multi-line text with `{{key}}` markup renders per-line segment colors instead of getting `null` segments.
- <span style="color: #ffc680"><strong>Orphaned derpSignalOut rows now pulse between DIS and ON states</strong></span>: Orphan signal entries use color-key state pulsing (`pulseStates: true`) to animate between `_DIS` and `_ON` palette colors, making orphaned signals visually distinct from normal disconnected/broken states. Orphan face labels also render with `t_text_error` color-key markup.
- <span style="color: #ffc680"><strong>LoRA trigger dropdown DIS state</strong></span>: Trigger dropdowns now display as disabled when the LoRA has no triggers available, not just when bypassed. LoRA trigger items simplified to use `t_text_highlight`.
- <span style="color: #ffc680"><strong>derpSignalOut defaults</strong></span>: `showSlotNames` now defaults to `true` for new signal out nodes.
- <span style="color: #ffc680"><strong>Signal picker label lookup</strong></span>: Both plain and color-key label formats are now registered in `_signalLabelToId`, fixing signal selection when color-key markup is active.
- <span style="color: #ffc680"><strong>derpSignalOut signal reference fallback</strong></span>: Signal resolution now falls back to `this.activeOutputs[idx]` when `globalSignals[sigId]` doesn't contain the entry, validated via `isSignalInCurrentGraph`. Fixes orphaned signal references when the global signal registry and active output array get out of sync after node graph changes.
- <span style="color: #ffc680"><strong>Color-key text rendering consistency</strong></span>: Color-key markup is now stripped from text measurement/cutoff/shrink calculations, missing color-key entries no longer force fallback colors, and unresolved segments render through the normal layoutMap text paint path.
- <span style="color: #ffc680"><strong>Per-segment text effects from palette string color keys</strong></span>: Palette string color entries now carry per-segment `shadow`/`glow` effect colors alongside fill colors. `masterPainterText` applies per-segment shadow/glow passes using the segment's effect color with the theme text key's offset/blur physics. HTML `textLabel` and `btnSimple` map per-segment shadow/glow to CSS `text-shadow`. Missing effect keys on a palette entry disable that effect for the segment entirely. Segments now merge only when both fill color AND effects match.
- <span style="color: #ffc680"><strong>Node 2.0 group-release dock drift</strong></span>: Moving a default ComfyUI group containing Derp docked stacks no longer nudges already-aligned vertical or horizontal stacks on mouse release. Vue-mode dock maintenance now skips shared-height sync and normalization when docked edges are already geometrically aligned.
- <span style="color: #ffc680"><strong>Image widget now shows a dark background fill behind images</strong></span>: When `drawBackground` is enabled, the image widget now draws a semi-transparent black fill (`rgba(0,0,0,0.5)`) behind the image area before the paintData background. The `hideBackgroundWhenImage` flag on derpImageDeck has been removed so the background is always visible — no more empty transparent gaps when images load in.
- <span style="color: #ffc680"><strong>System panel resize handles disabled</strong></span>: System panels (`fathaSysPanel`) now have their resize handles hidden systemically via `disableResizeHandles()` in `syncDerpShield` instead of an ad-hoc inline `style.display = "none"` hack. The old ad-hoc code in `toggleDerpSysPanel` has been removed. System panels also get `resizable = false` for good measure.
- <span style="color: #ffc680"><strong>Vertical dock resize min-height</strong></span>: `syncDockResizePair` now uses `getDockNodeMinHeight` per-node instead of a shared `minH`, preventing taller nodes from being crushed below their minimum when resizing vertical dock pairs.
- <span style="color: #ffc680"><strong>Pure vertical resize cursors</strong></span>: Top/bottom shared-edge resize anchors now show `ns-resize` cursor and block horizontal width changes instead of using the corner resize cursor. No more diagonal cursors on purely vertical drags.
- <span style="color: #ffc680"><strong>derpImageDeck height not snapping to 10px grid</strong></span>: Height in `resizeNodeToImageAspect` now snaps via `Math.ceil / SNAP * SNAP`. Bottom edge anchoring snaps to grid coordinates so the bottom edge stays put after page refreshes and latent aspect ratio changes.
- <span style="color: #ffc680"><strong>Horizontal docking height collapse</strong></span>: Nodes of different heights would collapse the taller node when docked horizontally (e.g., derpDiffusionLoader docked to derpSeedV2). Root cause was dual: (1) `fitSizesToTotal` initialized `assigned = minTotal` which double-counted minimums, causing single-node columns to receive `totalHeight - min` instead of the full target height. Changed to `assigned = 0`. (2) `applyColumnLayout`/`applyRowLayout` called `syncDeckNodeSize` non-silently, triggering an immediate `refreshNodeLayoutMap` that recalculated autoHeight and overwrote the normalized shared height. Changed to `{ silent: true }`.
